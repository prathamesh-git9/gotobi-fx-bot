NOT READY

The calendar, ordinary long/short schedule, default 55-pip stop and 30-pip long target are mostly implemented as specified. The safety claims are false under plausible terminal and network failures. **Do not leave this running unattended, including on demo, until the critical and high issues are fixed and retested.** A local PC cannot guarantee a timed exit while it or the broker connection is down.

## Findings, ranked

### CRITICAL

1. **Real-money account can be traded after startup.** `bot/engine.py:86-97`, `bot/engine.py:142-150`, `bot/main.py:118-133`. The two-key check runs once. If the user or an MT5 restart changes the terminal from demo to real while the Python process stays up, the next entry uses the real account without either key. Reproduced in `test_demo_to_real_account_switch_is_not_rechecked`. **Fix:** pin login, server and trade mode to the approved demo identity; recheck before every order, including after reconnect, and fail closed on a change. Persist the account identity in the journal.

2. **An ambiguous fill can become a duplicate trade.** `bot/broker.py:141-159`, `bot/engine.py:340-343`, `bot/engine.py:395-416`, `bot/engine.py:438-441`. History is queried only once *before* the first send. If MT5 executes an entry but the IPC reply is lost, the bot retries. An open position usually prevents the retry; if that position hits its stop before the next poll, there is no position and the bot does not recheck history. A second entry occurs in the same slot. Reproduced with a filled order whose response was lost and a next-minute stop in `test_ambiguous_fill_then_stop_can_duplicate_in_same_window`. **Fix:** write a durable intent before sending; treat `None`, timeout and connection errors as unknown outcome; reconcile order, deals and positions on every retry; do not resend until the prior request is definitively rejected or canceled. Test this across process crashes too.

3. **Timed exits cannot be guaranteed during disconnection, PC shutdown or terminal failure.** `bot/engine.py:308-329`, `bot/main.py:126-133`. Only the Python process sends the time exit. With a disconnect across 00:54, the long remains open after the fix; the server-side 55-pip stop does not enforce the time exit. Reproduced in `test_disconnect_across_exit_strands_position_until_reconnect`. This is a design limit, not just a retry bug. **Fix:** use a broker-side mechanism that actually enforces the deadline, or change the requirement to “close at the first available opportunity” and explicitly accept overnight/gap exposure. Test power-off and network-loss cases on demo.

### HIGH

4. **The short can be sent after the five-second limit and logged as on time.** `bot/engine.py:446-486`, `bot/broker.py:125-149`. The deadline is checked using `now` before account, symbol, sizing, tick and synchronous `order_send` calls. A slow terminal can send/fill at 00:55:10 while `sent_vs_fix_sec` records -1. Reproduced in `test_short_order_can_be_sent_after_deadline_while_logged_on_time`. **Fix:** use a fresh corrected clock immediately before submission; establish a timeout/fail-closed policy for slow calls; record actual deal time and never claim the deadline was met from the earlier poll timestamp. The broker's execution time still needs demo validation.

5. **A wrong PC clock can become a false broker offset.** `bot/clock.py:53-76`, `bot/engine.py:71-83`, `bot/engine.py:183-199`. Failed SNTP checks allow trading on the PC clock; old corrections are retained. With the PC one hour ahead and SNTP unavailable, automatic server-offset detection interprets the hour as a broker offset, considers prices fresh and buys one hour early. Reproduced through `main()` in `test_main_clock_server_failure_with_pc_one_hour_ahead_trades_early`. A failed refresh also retains a now-stale 20-second correction in `test_clock_failure_retains_stale_correction`. **Fix:** require a recent independent time check for second-sensitive trading; validate broker offset against a pinned/configured offset and limit sudden changes; halt entries on unresolved clock disagreement. Never use tick freshness as proof of correct UTC when estimating the offset from that same UTC clock.

6. **Other positions on the symbol are invisible to the entry guard.** `bot/broker.py:78-82`, `bot/engine.py:142-150`. `positions_get` is filtered to this magic number. A manual/other-EA sell in a hedging account remains open while this bot opens a buy. Reproduced in `test_broker_ignores_foreign_position_and_can_hedge`. **Fix:** query *all* positions for the selected symbol/account before entries; block any new entry while any position is open, while continuing to manage only the bot's own trades. Also check pending orders.

7. **The 50% drawdown switch is not checked while flat.** `bot/engine.py:283-299`, `bot/engine.py:345-347`, `bot/engine.py:443-445`. It runs only after a closing deal is finalized and uses balance rather than current equity. A 60% loss/withdrawal elsewhere while flat is followed by a new entry. Reproduced in `test_drawdown_is_not_checked_while_flat`. Exactly 50% also does not trigger because the comparison is `<`, not `<=`. **Fix:** check account equity against a durable peak before every entry and each poll; define how deposits and withdrawals adjust the peak; use `<=` for the 50% threshold.

8. **A corrupt state file aborts startup indefinitely.** `bot/journal.py:23-28`, `bot/main.py:98-111`, `run_bot.bat:7-13`. Invalid or truncated JSON raises outside the startup exception handlers. The batch file restarts every 30 seconds, hits the same error and never manages an open trade. Reproduced in `test_corrupt_state_aborts_main_before_watchdog_loop`. `os.replace` and file `fsync` reduce, but do not eliminate, power-loss and disk-corruption scenarios; the event log is not replayed for recovery. **Fix:** validate and back up state, recover from a prior durable snapshot plus broker orders/deals, and stop new entries until reconciliation is complete; alert an operator rather than silently looping.

9. **Placed and partial orders are treated as fully completed.** `bot/broker.py:32`, `bot/broker.py:148-149`, `bot/engine.py:402-408`, `bot/engine.py:479-486`. `TRADE_RETCODE_PLACED` means “order placed” and `DONE_PARTIAL` means only part completed, yet both are `ok` and immediately journaled as an open position. There is no `orders_get`/order-state reconciliation. A placed order with no position yet can be marked closed after 12 polls and fill later unexpectedly. **Fix:** distinguish completed deal, partial fill and outstanding order; track order tickets until terminal status and deal volume are final. [MetaQuotes return-code definitions](https://www.mql5.com/en/docs/constants/errorswarnings/enum_trade_return_codes) and [order execution behavior](https://www.mql5.com/en/docs/trading/ordersend) support this distinction. The fake never produces these outcomes, so existing replay tests cannot catch it.

10. **Single-instance protection is scoped to `state_dir`, not account/symbol.** `bot/main.py:48-61`, `bot/main.py:85-86`. A second config with another state directory can run concurrently on the same account. With different magic numbers, both enter; with the same magic, timing and early stop can still defeat the journal guard. **Fix:** lock a stable account/server/symbol identity or enforce exclusivity at a separate supervisor. Check account identity after connect before taking an account-specific lock.

### MEDIUM

11. **A supported sizing setting violates the minimum-lot rule.** `bot/config.py:48`, `bot/config.py:88`, `bot/sizing.py:33-40`. Setting `below_min_lot = "min"` permits up to twice the requested risk instead of skipping. Reproduced with a 1.0 risk budget and a minimum lot risking 1.5. **Fix:** remove the option or reject it for this strategy; always skip if the minimum lot exceeds the risk budget. The example config uses the safer default `skip`.

12. **Sizing uses an earlier quote than the actual order.** `bot/engine.py:385-408`, `bot/engine.py:463-485`, `bot/broker.py:125-149`. The stop and loss-per-lot are computed from one tick; `market_order` fetches another tick, and the fill can move again. The actual distance and risk can exceed 55 pips/`risk_pct`, especially around the fix. Gaps can also fill stops worse than their stop price. **Fix:** recalculate against the final request price with a worst-case deviation allowance; verify the fill and attached stop, reduce/close an out-of-policy position, and state that stop-loss risk is a target rather than a guaranteed cap. [MetaQuotes documents variable real deal volume and execution pricing](https://www.mql5.com/en/docs/python_metatrader5/mt5ordersend_py).

13. **Missing deal history silently erases trade performance.** `bot/broker.py:84-86`, `bot/engine.py:247-259`, `bot/engine.py:287-299`. `history_deals_get(position=...) == None` is treated as an empty result. After 12 polls, a gone position becomes `closed` with unknown P&L/R; it is omitted from the last-60-long kill switch. **Fix:** raise on a history error; keep the slot unresolved, retry with bounded alerts, and block new trades when risk accounting is incomplete.

14. **Unbounded audit/state growth and disk failure are not handled.** `bot/journal.py:23-44`, `bot/journal.py:50-59`, `bot/engine.py:53-55`. `events.jsonl`, all historical slots and in-memory per-slot log keys grow forever. A full disk causes journal writes to fail after orders may have been sent; the main loop then retries indefinitely. Four simulated months showed no explosive growth, but cannot establish years of bounded use. **Fix:** archive/rotate events, compact old slots while retaining the last 60 long R values and peak, reserve disk space, and alert/disable entries on persistence failure.

15. **Windows reboot recovery is only a manual setup instruction.** `run_bot.bat:5-15`, `BOT_README.md:56-64`, `BOT_README.md:93-102`. The batch file does not install a Task Scheduler task. Its recommended log-on trigger requires that the intended user actually logs on after reboot; MT5's interactive terminal/session and saved login must then be ready. `keep_awake` at `bot/main.py:64-69` prevents idle sleep only while the process runs; it cannot prevent lid/power-button sleep. Windows Update can still restart outside active hours. **Fix:** install and test an interactive-user log-on task with restart-on-failure, power/network prerequisites and alerting; set lid/power policy and update active hours; perform a real reboot/power-cut drill. [Microsoft log-on trigger](https://learn.microsoft.com/en-us/windows/win32/taskschd/starting-an-executable-when-a-user-logs-on), [sleep API limits](https://learn.microsoft.com/en-us/windows/desktop/api/winbase/nf-winbase-setthreadexecutionstate), [update active hours](https://learn.microsoft.com/en-us/windows/deployment/update/waas-restart).

16. **The batch file restarts after a deliberate normal stop.** `bot/main.py:134-146`, `run_bot.bat:8-13`. Ctrl+C returns code 0, but the batch file restarts the bot in 30 seconds; an operator may believe trading stopped. It also retries startup code 3 without a cap or alert. **Fix:** make an explicit stop code and end on it (and on 0 if that means intentional stop); use a supervised service/task with health checks and notifications for persistent startup failure.

### LOW

17. **Preflight can say READY on a real account without the command-line key.** `bot/engine.py:86-97`, `bot/engine.py:535-540`. `inspect_only=True` skips the two-key refusal, and preflight checks only config `allow_live`, not `--allow-live`. This does not itself place a real trade, but gives a misleading readiness result. **Fix:** pass both keys into the preflight report and call the real-account state “blocked” unless both are present.

## Rules and tests checked

- Calendar: `bot/gotobi_calendar.py:63-103` walks back over weekends, Japanese public holidays and the specified bank holidays, deduplicates moved dates, omits February 30/31, and skips dates that *land* on 25 December or 1 January. Existing calendar tests passed. Entry, fix, long exit and 30-minute short exit timestamps are correctly built in UTC. The default long delay/minimum hold/spread checks and broker-side SL/TP requests follow the stated thresholds in ordinary operation.
- Existing fast suite: `python -m pytest tests -m "not slow" -q -p no:cacheprovider --basetemp codex_audit/bot_review/pytest_base --tb=short` → **113 passed, 7 slow deselected**. The first attempt without a custom temp directory produced 73 `PermissionError` fixture errors because this restricted laptop cannot access pytest's default user temp root; rerunning inside this review directory passed. The 15-minute slow replay was not needed to establish the safety failures above and was not run.
- Independent tests: `python -m pytest codex_audit/bot_review -q -p no:cacheprovider` → **12 passed**. The four-month soak invokes actual `bot.main.main()` with `FakeMT5` as the imported package, simulated UTC/sleep, a mid-position process restart, `positions_get` failure, transient requote, fatal rejection, terminal disconnect, unexpected exception and time-server failure. It executed over 100,000 loop calls, checked every requested sleep is finite and within (0, 60] seconds, found no duplicate/hedged/stranded positions in that recoverable run, and found unaffected entry signatures identical to a clean run. Python allocated blocks were sampled monthly and grew by less than 100,000 across the samples. OS lock and logging setup were stubbed; this is not a test of Windows scheduling or live IPC. Additional focused tests deliberately reproduce unsafe outcomes; they pass by asserting the observed bug.
- Installed `MetaTrader5` 5.0.6231: existing `tests/test_api_surface.py` compared used names, constants and simulator result fields to the package and passed. Independent tests checked documented call forms for `initialize`, `positions_get`, `history_deals_get`, `order_calc_profit`, `order_calc_margin`, `order_check`, `order_send`, plus the other used functions/constants. These are compatible at the Python API surface. A disconnected installed package cannot validate server acceptance, filling policy, execution mode, commissions or live result semantics. [MetaQuotes Python API reference](https://www.mql5.com/en/docs/python_metatrader5).
- Test gaps: existing engine/replay tests call `Engine.step()` directly and use minute bars; they do not run `main()` unattended, model a response lost *after* broker execution, account switching, other-magic positions, delayed synchronous order calls, placed/partial orders, state corruption or a wrong PC clock. `FakeMT5` fills at a minute's opening bid/ask, provides a synthetic current-second timestamp, simulates stop/target touches from minute OHLC and returns immediate complete fills. It does not model real tick sequencing, IPC latency, broker queueing, pending/partial orders, terminal updates, netting behavior, live commission/swap or internet partitions faithfully enough to prove the absolute safety claims.
